# ACP binding conformance kit

Checks an agent over the [ACP host binding](../../docs/bindings/acp.md), `modular-agent-acp/1` and `/2`. Start the agent on stdio with the conformance model and tools. The kit creates a fresh `HOME`, project and local data directory. When `git` is on `PATH`, the project is an empty git repository (`git init`), so an environment that keeps saved points in git can declare `rewinding` for it. It passes through `PATH`, explicit fixture plugin settings, and the test history service settings. Use a launcher that does not need per-user tool lookup. The kit sets `MODULAR_AGENT_TENANTS` with restricted tenants for `tools` and `cancel`, one with zero tokens and two with a one-token budget.

Run only with isolated, disposable processes, workspaces and services. The project directory is not a sandbox. Use no ambient credentials, production configuration, plugins or data. Fixture tools write files and start local commands. Crash checks kill agent processes. The kit removes its temporary directories and leaves test sessions in any configured history service.

```sh
npm ci --prefix conformance/acp
node conformance/acp/run.mjs -- <agent command> [args...]
```

To run against the TypeScript build, run `npm ci && npm run build` in `typescript/`, then from there use `node conformance/acp/run.mjs -- node "$PWD/packages/agent/dist/src/cli.js" --acp`. Append `--durable` to that agent command to select its durable Runtime.

Use Node.js and a Bash/POSIX test environment. The ACP client dependency needs a registry or package cache for installation. Basic execution uses no external model or service. Use absolute executable paths in the agent command. `--verbose` prints stderr and passing details. Exit code 0 means all checks run passed.

|---|---|

| Session declaration and offered extensions | Joining an actor does not grant presence or representation. Also checks proposal release and withdrawal, recorded rights changes, refusal to move inside a turn, completed rewind on reopen, session-qualified erase results and erased duplicate receipts on both admission routes, session ceilings, a zero tenant budget, and idle versus busy close for a tenant member without `cancel`. |
| Session explicitly declares `severalActors`, `sessionLimits` or `tenants` false | Check `not_supported` for proposed input and joining another actor, changing the session limit, or querying the tenant, respectively. This does not require removing the methods from the connection's union of extensions. An agent that can park job reports or reopen them still parked must still offer `proposals`, `release` and `withdraw`. |
| Full conformance fixture | Run the fixture tool `nest`. Check that the nested call is announced with its parent, settles once, is recorded as started by a tool under its parent in the parent's turn and step, and appears in no model response. Check that an unknown nested tool is recorded and refused without starting. The fixture must declare `nestedToolCalls`. |
| `--plugin-checks` | Set `MODULAR_AGENT_PLUGINS` to a fixture plugin command configured to serve only the `hooks` part. See [the conformance plugin](../../docs/bindings/plugin.md#the-conformance-plugin). Check a refused tool, stream redaction and a redacted history projection. |
| `--probe-checks` | Load the probe plugin. In separate launches, check that an early plugin exit or refused registration fails startup without a successful `initialize`. Check history cursors and page count bounds, callback scope, method errors, early-arriving cancellation, gate payloads and rejected gate mutations, a tool refresh barrier, no replay when the gate withholds `session/load`, and answering a text question without forms (including a late answer when declared). Also checks that `answerable` is absent before gating and false on a redacted approval view, that an altered view cannot authorize an answer, and that a failed catalog refresh does not hide a completed result. For a session that declares rewinding with the fixture environment, it checks every later point before saving or restoring. Runtime fixtures check exact-call dispatch, environment callbacks under a dispatched call, out-of-phase callbacks, record ownership, result acknowledgement, the committed result of a refused call, refusal of an unoffered tool and steering after the final check. A Provider probe adds an unknown response callback member. With tenant support they check a limit latched after a step. With tenant support and a history service they also pause one intent reply while another session uses the budget, then inspect the host's aborted response. |
| `--job-checks` | Load the jobs plugin. Check acknowledgment, deduplication, exact report admission, declared scheduling and cancellation if offered. The parked-report check runs only if the session does not declare `startsTurnsUnasked: "jobReports"`; the runner reports it as skipped otherwise. With a history service, observe the actual append batch for the report. With `--crash-checks`, check take-up after loss and refusal to resume a job already running on the plugin connection. |
| `--crash-checks` | Kill the agent while the fixture's non-repeatable command is running. Check that it did not finish if within declared containment, then check one `outcomeUnknown`, no replay and the reopener's declared recovery outcome. With `--probe-checks`, crash before and after `step.after` and check which gate runs on resume. With a service declaring a TTL from 1,000 to 15,000 ms inclusive, delay a successful renewal reply and check that it does not restore dispatch authority. With any test service, a simulated restart hold longer than the reopen budget checks the retryable ACP error. |
| `--portable-checks` | Require a shared history service and the portability declaration. Sample kept fixture logs for fields, order, associations and tombstones, including recorded model offers and grant provenance. Compare same-principal and different-principal retries after reopen. Reopen seeded histories with narrowed or revoked rights, a tombstoned hand-back with its input ID, a cleanup marker and a parked job report. List and release the parked report even if `severalActors` is false. When recovery runs older queued input, check that fresh work cannot overtake it or receive `now` while it waits behind it. Test an unknown approval value when approvals are offered. If the source declares forking, seed a branch over 64 MiB in separate batches and inspect history HTTP requests for any destination write. Check the retryable ACP error for a simulated restart hold. With `--probe-checks`, inspect raw approval bindings and pending and continuation records when supported. Also check remote Runtime recovery: settled calls excluded from resume, empty failed attempts excluded from default context, and abort, fresh preparation and exact replay of interrupted model attempts. Check that a remote Provider request commits at the request hook and that an uncommitted response is refused. A normal portable run without `--probe-checks` does not run these remote Runtime or Provider cases. |

## ADR 0030 checks

Use `--group NAME` to select one transcript: `core` (the local default), `covered`, `waiting`, `isolation`, `capacity` or `erasure`. A selected group needs its own fixture. The full managed check runs all six; `scripts/production-kits.sh` supplies the [ADR 0030](../../docs/adr/0030-production-gaps.md) policies and disposable stores.

| Enable | What the agent needs and what the kit checks |
|---|---|
| `--group isolation` | Use the kit's operator policy, two projects, two named tenants and an unassigned tenant. Check startup refusal, actor selection, exact canonical project matching through symlinks, setup and MCP counters, discovery and cursors when offered, scope on load and resume, and connection ceilings on input, fork and answers without changing the recorded grants. Where `severalActors` is declared, check configured representation and both recorded identities. On a shared listener, revoke a viewer while the output gate holds its history reply and check that it gets no content. |
| `--group capacity` | Enforce the small reservation limits set by the kit's policy. Race admissions for the last pending slot at session, tenant and agent scope. Check `busy` before any receipt, deduplication, reuse of a refused key and independent tenant buckets. Settle a held question and call at saturation. Use an explicitly released fixture job to check a refused second start, an exact report transfer and cancellation at saturation. In `/1` and `/2`, a remote fixture Provider supplies two calls against a one-call ceiling: check retained usage, one bounded failed response, no dispatch and a `capacity` turn limit. Repeat with a wire Runtime and check the ordered model, record, `step.after` and `turn_limit` callbacks. |
| `--group erasure` | Set `MODULAR_AGENT_HISTORY_URL` and `MODULAR_AGENT_HISTORY_TOKEN_FILE` for a shared disposable service. The service must offer `pendingErasure: 1`. Each writer uses a separate home and data directory. Hold a raw lease on the fork of a fork, crash the initiator, and verify the reader does not serve pending content, the next writer reconciles before replay, the key is still spent and the report converges without extra bookkeeping. Repeat with the source bookkeeping append or tombstone committed but its HTTP reply withheld. With `--then`, the second launcher must use the same HTTP registry. |

The kit writes `policy.json` beside the isolated `ma` configuration. A base agent without that default path takes the same file from `MODULAR_AGENT_CONFORMANCE_POLICY` in [conformance mode](../../docs/bindings/acp.md#conformance-mode). The kit supplies all token files and limits; do not give the launcher a different operator policy. A fixed-project composition cannot run the two-project case: give the launcher a composition factory that serves both fixture projects.

With `--connect`, these checks require `--service-command`. For the test policy variants that contain `actors`, start `ma --acp --listen "$MODULAR_AGENT_CONFORMANCE_URL"` without the single-token shorthand. For ordinary variants (where `MODULAR_AGENT_CONFORMANCE_POLICY` is unset), also pass `--token-file "$MODULAR_AGENT_CONFORMANCE_TOKEN_FILE"`. The kit uses multiple credentials on the same policy listener. A bridge which starts a new process per connection does not test the same listener's attachment and authorization rules.

`--group covered` checks one live and one waiting covered approval on each ACP binding. Run a kept, approval-enabled composition (`ma --acp --approval off`); the kit provides the operator maximum. It checks the permission and poll, then verifies the child start names the parent and request, including in the continuation. It fails if coverage, waiting approvals or nested tools are missing. Do not use this maximum for core Runtime probes.

## Waiting approval checks

Pass `--group waiting` to the managed fixture launcher. For ACP /1 and /2 each case checks its own declaration and session options. The fixture starts in live mode; the client selects `untilDeadline` over ACP. Do not run these cases on a deployed listener. WebSocket launch requires `--service-command`. A portable `--then` pairing requires a disposable shared store.

The cases run on each binding. They cover live refusal with no approver present, a poll before turn end, history and changed/blocked views, connection and actor scope, two decision races, loss of rights versus disconnect, eight reopen boundaries and failure modes, fork/rewind/move, two erasure targets and the call reservation across reopen. The branch, multi-member, erasure and capacity cases require their respective declarations. The kit checks the actual project file as well as the committed entries and batches. No permission request is expected. The control fixture is not evidence that any SDK passes.

**Launcher contract.** The full check runs each SDK’s [fixture command](../sdk/fixtures/) with the argument `acp-waiting`. It serves the conformance agent on stdio, an authenticated ACP listener for the other principals, and a loopback control service. `MA_ACP_WAIT_FIXTURE` names a private JSON file with the case `name`, ACP `version`, test `project`, `maxApprovalWaitMs`, paths `clock` and `ready`, and disposable `tokenFiles` by role. In conformance mode only, compose kept history, the approval gate, conformance/echo and the ordinary bash tool. Use the integer in the clock file as the Harness time, including on startup. Keep the same store, principals, project and writer scope on restart. In the capacity case set one session call slot. For `reopen-afterEffect`, hold the non-repeatable bash invocation after its write and before its result can commit. Never dispatch from the fixture controls.

The primary ACP connection runs the worker. Give it input, tools, settings and the administrative rights needed for branch/erasure checks, but no answer route. Seed two eligible offline members (`approver` and `other`, with watch and approve but not tools). In a single-member composition use the same member on distinct routes with different connection ceilings. The `representative` can act for the approver, but its own poll is not a delivery for that actor. `answerOnly` has watch and answer, not approve. `tenant` is outside the session's tenant. Do not make any of these actors present at startup. The kit attaches each on a **real**, separately authenticated ACP connection to the same writer, even when the worker uses stdio.

Before replying to initialize, the fixture launcher writes `{acp, control}` to `ready`: the numeric-loopback WebSocket URL and a separate loopback HTTP test URL. The latter accepts only the control bearer and a JSON POST `{operation, sessionId, ...}`; return HTTP 200 and a JSON object after the operation.

| Control | What the fixture does |
|---|---|
| `inspect` | Return `{batches}`: the current shared records grouped by their actual store writes, including terminal tombstones. Retain batch boundaries across stops. |
| `idle`, `tick` | Wait for runnable work to settle; do not wait for future answers. On tick, observe the new clock and process due closures, without blocking on a held handoff. |
| `pause`, `reached`, `release` | Arm, wait for, or release a named latch (`at`). A release without a name releases all latches. Latches stop work outside the writer lock, not the control endpoint or unrelated ACP requests. Boundaries: committed `requestPending` before origin end, `answerCommit` before taking ready work, `continuationStart` before dispatch, `beforeHandoff` before the final authority/deadline check, `afterEffect` before result commit, and `pendingErasure` before tombstoning. Discard latches, never committed data, on process loss. |
| `gate` | Set the named role's requests output gate to `redact` the call input, `block` the reply, or `pass`. |
| `revoke` | Revoke the named member's `right` through the authority system. Keep watch and answer for negative acknowledgements. |
| `cut` | `worker-ceiling` removes tools from the session ceiling; `approver-rights` revokes approve; `route-authorization` removes authorization of the recorded answer route; `stale-writer` fences the writer in the store. Do not use socket loss to implement revocation. |
| `barred` | Wait for held work to observe the pending erasure and abandon its handoff, before completing deletion. |

Only in the two corrupt/unsupported reopen cases the new launch file has `reopen`: `unsupported` omits the feature, or `missing-proof` drops the allow's private view binding in the disposable store before the new writer acquires it. In both cases the old decision cannot run the tool. Run `npm test` here for the kit’s self-tests.

## Over WebSocket

To check an agent served over the [WebSocket transport](../../docs/bindings/websocket.md), give the kit the service's address and a file holding its bearer token instead of a command:

```sh
npm ci --prefix conformance/tools
node conformance/acp/run.mjs [options] --connect ws://127.0.0.1:PORT/ --token-file FILE \
  [--service-command COMMAND] [--actor ID] [--other-token-file FILE]
```

The kit runs the default checks over the connection, plus transport checks: an upgrade with no token or a wrong token is refused with HTTP 401, an upgrade without the subprotocol is refused, and two connections with the same token are independent ACP connections acting as the token's actor. `--actor` names the actor the token should select. `--other-token-file` holds a token for a different actor; with `--portable-checks` or `--then`, it runs the retry-by-a-different-principal check, which is skipped without it.

`--crash-checks`, `--probe-checks` and `--job-checks` need to kill and restart the service and to start it with fixture plugins. Give `--service-command`, a shell command that starts the service; the kit runs it with `MODULAR_AGENT_CONFORMANCE_URL` and `MODULAR_AGENT_CONFORMANCE_TOKEN_FILE` set, and starts extra copies on other loopback ports when a check needs a different startup configuration. Without `--service-command`, those checks are skipped with the reason.

To serve a stdio agent over WebSocket, use the bridge, `conformance/tools/ws-bridge.mjs`, a disposable, loopback-only test adapter that starts one agent process per connection. With no `--listen` or `--token-file`, it reads the two variables above, so it can be the service command:

```sh
MODULAR_AGENT_CONFORMANCE=1 node conformance/acp/run.mjs --crash-checks --probe-checks --job-checks \
  --connect ws://127.0.0.1:39211/ --token-file FILE \
  --service-command "node $PWD/conformance/tools/ws-bridge.mjs --binding acp -- $PWD/rust/target/debug/ma --acp"
```

Results through the bridge: Rust `ma`, 96/96 with the default checks and 193/193 with the three options above (stdio: 188/188); the Rust base agent, 219/219 (stdio: 214/214). The bridge accepts one token, so it cannot exercise `--other-token-file`. Each `ma` serves ACP itself with `ma --acp --listen ADDR --token-file FILE`; [`scripts/websocket-kits.sh`](../../scripts/websocket-kits.sh) runs the kit against each with no bridge: 193/193 in all four languages.

, the rights checks accept a completed turn with a refusal or a failed turn with `Invalid tool directive`. They check that no dispatch was recorded, the command did not run, and no result came from the tool. See [Tool dispatch](../../docs/contracts.md#tool-dispatch), [Prompts](../../docs/bindings/acp.md#prompts) and [Conformance mode](../../docs/bindings/acp.md#conformance-mode).

For a local service, use the [history kit setup](../history/README.md). Its 2,500 ms TTL and the reference service's 15,000 ms default both exercise the delayed-renewal probe. If the service declares a TTL outside 1,000 to 15,000 ms, use a disposable instance in that range. Point both agents at the same service:

```sh
MODULAR_AGENT_HISTORY_URL=http://127.0.0.1:39071 \
MODULAR_AGENT_HISTORY_TOKEN_FILE=/path/to/disposable/token \
  node conformance/acp/run.mjs --crash-checks --portable-checks \
  -- <agent A> [args...] --then <agent B> [args...]
```

After `--then`, B reopens A's sessions for load and enabled recovery checks; both use the same store. The independent `/2` probe still uses A. Allow both launchers to open the fixture project. The kit sets [`MODULAR_AGENT_ACTOR`](../../docs/bindings/acp.md#starting) to the same id for the writer and reopener. It starts a separate reopener with a different id to check that the same key admits new input without exposing the first receipt.

The kit does not test all declarations or malformed wire values. It does not establish independent principal or tenant isolation, question recovery across a process restart or secret question handling, general budget accounting across lifecycles and deployments, arbitrary history migration, or erasure across external copies and backups. Early-arrival cancellation is not proof of pre-dispatch cancellation. The rewind journal is inspected only with a history service. The fork preflight check leaves about 65 MiB in the disposable store. It checks that an oversized history HTTP fork writes nothing, not how the client estimates the size of a borderline batch. The remote recovery fixture covers interrupted model attempts, not a crash between `toolPending` and `turnEnd`. The queue fixture does not force an idle scheduling gap, and the report check relies on the selected build to exercise a session without `severalActors`. Watchdogs limit the kit run; they do not add protocol deadlines. Passing is not proof of [conformance](../../docs/conformance.md#what-conforms).
