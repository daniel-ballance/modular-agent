# Decision draft: reasoning in the API-key Providers

Open. This proposal covers the SDK's `openai()` and `anthropic()` Providers, not subscription adapters. Vendor pages were fetched and checked on 2026-11-21.

## What the APIs accept

**OpenAI.** [Responses create](https://developers.openai.com/api/reference/resources/responses/methods/create) takes `reasoning.effort`. The [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort) lists `none`, `minimal`, `low`, `medium`, `high`, `xhigh` and `max`, but support and the default vary by model. [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) takes `none`, `low`, `medium` (the default), `high`, `xhigh` and `max`. [GPT-5.2](https://developers.openai.com/api/docs/models/gpt-5.2) takes `none` (the default), `low`, `medium`, `high` and `xhigh`. [GPT-5](https://developers.openai.com/api/docs/models/gpt-5) takes `minimal`, `low`, `medium` and `high`. The [Models API](https://developers.openai.com/api/reference/resources/models/methods/retrieve) returns model identity and ownership, not an effort list. A discoverable id is not evidence of which efforts it accepts.

**Anthropic.** The [thinking support table](https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting#thinking-support-defaults-and-rejected-configurations-by-model) lists the supported modes, defaults and exceptions by model. With adaptive thinking, send `thinking.type: "adaptive"` and set `output_config.effort` separately. The [effort table](https://platform.claude.com/docs/en/build-with-claude/effort#effort-levels) lists `low`, `medium`, `high` and, on some models, `xhigh` and `max`. [Adaptive thinking](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost) is soft guidance, not a fixed budget. Some models accept `thinking.type: "disabled"`, some cannot disable thinking, and some only accept `disabled` at certain efforts. Sonnet 5.5's `between_tools` mode does not turn thinking off. [Manual extended thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking#budget-rules-and-tuning) uses `thinking: { type: "enabled", budget_tokens: N }`, with a minimum of 1,024 and normally strictly below `max_tokens`. Thinking counts against that output allowance. Claude 4.6 deprecates manual mode and 4.7 and later reject it; use adaptive when both are supported. Anthropic's [Models API](https://platform.claude.com/docs/en/api/models/retrieve) reports capabilities, including effort levels and thinking modes.

## Options

1. Use one lowest-common-denominator list and fixed mappings across vendors. This hides useful settings and cannot reliably make `off` work for every model.
2. Ship the same documented per-model table in all four SDKs. Update it as part of SDK releases and test requests offline. This works without credentials or network access at composition time. The table will lag new models.
3. Discover capabilities at runtime where a vendor exposes them, and allow operator-supplied capability entries for other models. This is more current but adds authentication, caching and failure policy at catalog refresh. OpenAI discovery alone cannot supply effort metadata.

**Recommendation: 2.** Make the table the source of both `ModelInfo.thinking` and the adapter's request mapping. Check the exact API model id, including explicitly listed aliases; do not infer from a name prefix. Do not copy one language's dependency catalog unchecked. Option 3 can follow if catalog freshness becomes a requirement.

## Proposed mapping for option 2

The shared [Reasoning](../bindings/data.md#models) vocabulary is `off`, `minimal`, `low`, `medium`, `high`, `xhigh`. Do not advertise vendor `max` as a distinct level or silently alias it to `xhigh`. For a selected level that is not offered, apply the existing fallback: use the nearest listed level no higher, or omit reasoning settings when none qualifies. An unset setting leaves the vendor default in place; it does not mean `off`.

| Model capability | List | Send for an explicit offered level |
|---|---|---|
| OpenAI with documented effort support | Documented levels in the shared vocabulary; list `off` only for `none` | `reasoning.effort: "none"` for `off`; send the same effort string for every other level. Luna lists `off`, `low`, `medium`, `high`, `xhigh`; GPT-5 lists `minimal`, `low`, `medium`, `high`. |
| Anthropic with adaptive and effort support | Documented `low`, `medium`, `high` and `xhigh`, as supported; list `off` only when disabled thinking is supported | For a positive level, `thinking: { type: "adaptive" }` and `output_config: { effort: level }`. For `off`, `thinking: { type: "disabled" }` and omit effort, provided the documented default permits `disabled`; otherwise use a documented compatible effort, or do not offer `off` if none is suitable. Sonnet 4.6 lists `off`, `low`, `medium`, `high`; Opus 5.5 lists `low`, `medium`, `high`, `xhigh`. |
| Anthropic with manual thinking only | `low`, `medium`, `high`; add `off` only if it can be disabled | Set `thinking.type: "enabled"` and use SDK budget targets 1,024, 4,096 and 8,192 respectively. Cap the budget at `max_tokens - 1`; if there is not room for even 1,024 thinking tokens, leave manual thinking disabled for that request. Use `thinking.type: "disabled"` for `off`. For a manual-only model that also accepts effort (Opus 4.5), send the corresponding `output_config.effort` for positive levels as well, as Anthropic [advises](https://platform.claude.com/docs/en/build-with-claude/extended-thinking#budget-rules-and-tuning). |
| Known model without a verified mapping | No explicit levels, not `off` | Omit reasoning controls. Report `reasoning` capability separately; having no selectable levels does not prove that the model never reasons. |

For a model id absent from the SDK catalog, do not list it or admit a request for it. Use the existing unknown-model errors at each boundary. If an existing constructor explicitly enrolls a custom id with its limits and input types, treat it as a known entry **without** a verified mapping unless the operator explicitly supplies verified capability data. Omit reasoning controls for that entry. Do not probe with a billable request to guess its support or retry a vendor rejection with another level.

Check representative requests offline: Luna `off` and unset; GPT-5 with an unsupported `off`; adaptive models with and without disable support; a manual budget limited by `max_tokens`; and an explicitly enrolled id with no verified settings. On Anthropic tool follow-ups, preserve the vendor-required thinking blocks without exposing opaque data to other Providers or recipients.
