# AG-UI 1.0

Checked 2026-11-23. Sources: the [published 1.0 specification](https://docs.ag-ui.com/spec/1.0/index), the [normative JSON Schema](https://github.com/ag-ui-protocol/ag-ui/blob/c31e1e819e3a3c3b4af14add04f5b9a9a0208cae/spec/1.0/schema.json) and the [first-party repository at release/2026-11-21](https://github.com/ag-ui-protocol/ag-ui/tree/release/2026-11-21). The live docs have a separate draft. SDK package versions are not protocol versions.

## What goes in

[`RunAgentInput`](https://docs.ag-ui.com/spec/1.0/basic/run-input) is the only consumer-to-producer message per exchange. It requires `threadId`, `runId` and ordered `messages`. The producer treats `messages` as the complete history it is shown, not necessarily its own complete record. Activity messages must be stripped before sending. User and tool messages can carry multimodal parts. Unsupported parts are skipped; a `file` source is an opaque Provider handle, not a URL to fetch.

Optional fields are `parentRunId` (a spawning run, not the previous sequential run), `protocolVersion`, `tools` (frontend tool offers), `context` (description/value pairs intended for model grounding), `state` (last agreed value, default `{}`), `forwardedProps` (opaque application JSON; top-level null means absent) and `resume`. An absent tool or context list is empty. `RUN_STARTED.input` may echo the request but need not. [Capabilities](https://docs.ag-ui.com/spec/1.0/basic/capabilities) describe what a producer offers; observed output still governs.

## What comes out

The [event model](https://docs.ag-ui.com/spec/1.0/basic/index) and schema list these 31 types. A run can contain several independently framed streams. IDs link their events; optional timestamps are not ordering keys.

| Family | Events and behavior |
|---|---|
| [Lifecycle](https://docs.ag-ui.com/spec/1.0/events/lifecycle) | `RUN_STARTED`, `RUN_FINISHED`, `RUN_ERROR`; `STEP_STARTED`, `STEP_FINISHED`. A stream opens with a start or error. Steps are labels, not necessarily model calls. On a normal close all open sequences must close. A failure can end them. A new run can follow a terminal event; a late error can follow a finish. A terminal event may carry per-Provider/model token usage. Limits can end as `cancelled`. |
| [Text](https://docs.ag-ui.com/spec/1.0/events/text-messages) | `TEXT_MESSAGE_START`, `TEXT_MESSAGE_CONTENT`, `TEXT_MESSAGE_END`, `TEXT_MESSAGE_CHUNK`. Chunks abbreviate the open/append/close pattern. Restate existing text with a snapshot, not deltas. |
| [Tools](https://docs.ag-ui.com/spec/1.0/events/tool-calls) | `TOOL_CALL_START`, `TOOL_CALL_ARGS`, `TOOL_CALL_END`, `TOOL_CALL_CHUNK`, `TOOL_CALL_RESULT`. Arguments accumulate as JSON text. End means the arguments are complete, not that execution succeeded. Results can carry text or parts. |
| [Reasoning](https://docs.ag-ui.com/spec/1.0/events/reasoning) | `REASONING_START`, `REASONING_MESSAGE_START`, `REASONING_MESSAGE_CONTENT`, `REASONING_MESSAGE_END`, `REASONING_MESSAGE_CHUNK`, `REASONING_END`, `REASONING_ENCRYPTED_VALUE`. Readable reasoning has a group and message framing. Encrypted values are opaque continuity data, not display text. |
| [State](https://docs.ag-ui.com/spec/1.0/events/state) | `STATE_SNAPSHOT` replaces state; `STATE_DELTA` applies RFC 6902 JSON Patch. Before the first snapshot, the delta base comes from run input. `MESSAGES_SNAPSHOT` reconciles conversation messages by ID. |
| [Activity](https://docs.ag-ui.com/spec/1.0/events/activity) | `ACTIVITY_SNAPSHOT`, `ACTIVITY_DELTA`. An identified, typed progress item in the UI's message sequence; the patch changes its content, not its identity. |
| [Subagents](https://docs.ag-ui.com/spec/1.0/events/subagents) | `SUBAGENT_STARTED`, `SUBAGENT_FINISHED`, `SUBAGENT_ERROR`. `subagentRunId` attributes events to an agent within the run. Subagents have their own state and can be nested. A suspended finish can reference the parent run's interrupts. |
| [Pass-through](https://docs.ag-ui.com/spec/1.0/events/passthrough) | `RAW` has an `event` and optional `source`; it carries foreign events. `CUSTOM` has a `name` and `value`; it carries application extensions. Neither can replace a described event or modeled field with the same meaning. |

## Two ways to stop for outside work

- [Interrupt](https://docs.ag-ui.com/spec/1.0/basic/patterns/interrupt-resume): `RUN_FINISHED.outcome` is `{ type: "interrupt", interrupts: [...] }`. An interrupt has `id` and `reason` and may carry a prompt, tool ID, response schema or expiry. A new run on the same thread answers every interrupt of the most recent interrupted run with `resume` entries: `interruptId`, `status` (`resolved` or `cancelled`), optional `payload` and `metadata`. Omission is not abandonment. Coverage is the consumer's responsibility. A producer that knows a question is still open must not act as if it were answered. A producer need not retain checkpoints to be conforming upstream.
- [Frontend tool](https://docs.ag-ui.com/spec/1.0/events/tool-calls#frontend-tools): the application advertises the tool in `tools`. The producer emits its arguments and leaves the call unanswered. If this is the only reason the run stops, the finish is a success, preferably with `pendingToolCallIds`. When a run also has ordinary interrupts, the pending tools are derived from unanswered call events. The application executes or declines after the finish. A subsequent run supplies a tool message per pending call, keyed by `toolCallId` (a string `error` on failure, in the input tool message, not the event). It does not answer the call via `resume`. The producer cannot fabricate a frontend result in the opening run.

## Processing, wire and versions

[Processing](https://docs.ag-ui.com/spec/1.0/basic/processing) is decode, middleware, enforce, verify, apply. Middleware can translate old or foreign events before enforcement. Enforcement drops unknown event types and strips unknown fields in closed shapes, with warnings. Open payloads such as metadata, state, `RAW.event` and `CUSTOM.value` survive. A malformed known value is fatal, as is a sequence violation. Unknown run input fields are stripped rather than rejected. The [TypeScript enforcer](https://github.com/ag-ui-protocol/ag-ui/blob/c31e1e819e3a3c3b4af14add04f5b9a9a0208cae/sdks/typescript/packages/client/src/enforce/enforce.ts) implements this distinction.

[HTTP + SSE](https://docs.ag-ui.com/spec/1.0/basic/transports/http-sse) is mandatory for HTTP implementations: UTF-8 JSON POST, then `text/event-stream` with one event JSON object per SSE `data` frame. SSE IDs and `Last-Event-ID` do not resume an exchange. A pre-stream rejection uses HTTP; in-stream failure uses `RUN_ERROR`. Truncation is not success or cancellation. [HTTP + Protobuf](https://docs.ag-ui.com/spec/1.0/basic/transports/http-protobuf) is optional: same request, response negotiated with `Accept: application/vnd.ag-ui.event+proto`. Frames have a four-byte unsigned big-endian length followed by one event. Unknown Protobuf fields may disappear in decoding; unknown event arms without a decoder representation are dropped with a warning.

[Versioning](https://docs.ag-ui.com/spec/1.0/basic/versioning): input and `RUN_STARTED` each declare their own version, not an agreed echo. Absence indicates an older, unversioned peer. A newer minor of a supported major must still be served; an unparseable declaration is treated like a newer one. Unsupported majors can be rejected. A downgrade preserves identity, order and outcome, cannot repair malformed known values and must warn on real loss. Retired shapes should translate in middleware.

For Modular Agent, the producer's record can remain authoritative without treating the consumer's copy as authority. This is a narrower policy than AG-UI requires. Core questions and Interface-run calls need distinct answers on the wire. The [Modular Agent binding](../bindings/agui.md) maps both without using a tool result as permission.
