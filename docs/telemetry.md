# OpenTelemetry profile (`telemetry: 1`)

An optional conformance profile, accepted in [ADR 0032](adr/0032-telemetry.md). Version 1 records metadata only: spans, timings, usage and errors, never content. Later versions add to it; see [What later versions add](#what-later-versions-add). Background is in the [research note](research/opentelemetry-genai.md).

## Ownership and declaration

The Harness MUST own the context for work it mediates. In-process parts receive the current context with the work. An event follower can report what it sees, but it cannot supply this profile. It does not see every operation or own the recovery checkpoint.

Each project SDK MUST instrument through its language's OpenTelemetry API. It MUST NOT install a telemetry SDK, exporter or global sampler on behalf of the app. Without an installed OpenTelemetry SDK the instrumentation is a no-op. The app (or `ma`) chooses the OpenTelemetry SDK, exporter and sampling. Telemetry collection and export MUST NOT be required for work to proceed. Export failure MUST NOT cause an effect to be repeated or change a committed outcome.

A conforming Harness declares `telemetry: 1` in the agent [declaration](contracts.md#declaration) and its session projection. Omission means no profile claim. This reports support, not whether export or content capture is on. Peers MUST work without context propagation. A claim does not imply that a remote part records spans.

## Spans and events

Use the [GenAI conventions v0.1.0](https://github.com/open-telemetry/semantic-conventions-genai/tree/v0.1.0/docs/gen-ai) for the signals mapped here. This profile does not require other GenAI signals. All `modular_agent.*` spans below are `INTERNAL` except `modular_agent.plugin.request`, which is `CLIENT` on send and `SERVER` on receipt. A span describes observed work, not a reconstruction from history. An event below is an OpenTelemetry span event, not an agent event or a history entry.

Use the Harness's stable session identity as `gen_ai.conversation.id` on session-scoped spans, including non-GenAI spans. If session IDs can collide in one export scope, use an opaque stable encoding of the scoped identity. A fork has a different identity. Do not use the Provider's retained conversation ID or the trace ID. Set `modular_agent.turn.id` and `modular_agent.step.id` to the Harness IDs on operations in those scopes. Use the executing turn for a resumed or inherited call. These and other opaque work IDs are span and event attributes, not span names or metric dimensions.

| Work | Span or event | Parent and attributes |
|---|---|---|
| Session | No lifetime span. Use `modular_agent.session.open` for new, load or resume, and `modular_agent.session.close` for close. | Parent to the initiating operation, if any. Set `modular_agent.session.operation` to `new`, `load`, `resume` or `close` and include the conversation ID once known. Do not keep a span open between operations. |
| Input admission | `modular_agent.input.admit` | Parent to the authorized input request context, if trusted. End when the admission is accepted, refused or resolved as a duplicate. Set `modular_agent.input.id` when a receipt is available. A turn can use the admission's context after that span ends. |
| Turn | `invoke_agent {agent.name}`, `INTERNAL`, or `invoke_agent` without a name. | Parent to the initiating work context, if trusted and available; otherwise start a trace. Set `gen_ai.operation.name=invoke_agent`. Start before committing `turnStart`; end after `turnEnd` or on observed interruption. Set `modular_agent.turn.outcome` to the recorded outcome kind, or `interrupted` if work stopped with no outcome. Waiting in place is part of this span. A submission that never starts a turn has no invocation span; if the `turnStart` write has already been attempted, a failed write ends the span as interrupted. |
| Step | `modular_agent.step` | Child of the turn. Include preparation, the model attempt and all calls until settled or left open. A recovery span covers only work done in the new segment, with the recorded step ID for a restored step. |
| Model attempt | `chat {request.model}`, `CLIENT` (`INTERNAL` for in-process inference). Use the actual GenAI operation name for a different inference operation. | Child of the step, or of the calling operation for an auxiliary attempt. Set `gen_ai.operation.name`, `gen_ai.provider.name` and the final `gen_ai.request.model`. Use the vendor convention where known; `modular_agent.provider.id` holds the registered Provider ID. Record available safe response model, finish reasons, stream flag, and reported token counts in `gen_ai.usage.*`. Start at the Harness's Provider request boundary, before invoking the Provider; end when its reply, stream or failure settles. Measure that boundary even if content is attached later. Each actual retry has a new span and step ID. A bookkeeping settlement is not an attempt. |
| Tool call | `execute_tool {tool.name}`, `INTERNAL` | Child of the step or of the operation that dispatched an out-of-turn call. Set `gen_ai.operation.name=execute_tool` and `gen_ai.tool.name` to the registered name. Set `gen_ai.tool.call.id` only for a model- or Provider-supplied ID, and `modular_agent.tool.call.id` to the Harness call ID. The span starts at dispatch and ends when the invocation settles or leaves the call open. Set `modular_agent.tool.status` to the shared result status, or `pending` if left open. A refusal before dispatch is a `modular_agent.tool.disposition` event with the same IDs and status, not an execution span. Provider-run tools with no observed execution boundary are reported by that event when their result is observed. |
| Nested call | Same as tool call; child of the active parent tool span. | Include `modular_agent.tool.parent_call.id` with the Harness parent call ID. Parallel siblings have separate contexts. If an open call is later dispatched, create a new span under the current operation, with the same call ID, not a reopened span. |
| Job | `modular_agent.job` | Parent to the operation that starts it, if any. Set `modular_agent.job.id`. The job can outlive its parent. End on settlement or loss of observation, with `modular_agent.job.outcome` from the job outcome or `interrupted` if unknown. Link a later report admission or renewed observation to the job span when its context is available. A duplicate receipt is not a job start. |
| Question | `modular_agent.question.open` and `modular_agent.question.close` events on the operation that opens or closes it. | Set `modular_agent.question.id` and `modular_agent.question.kind` from the input request. Set `modular_agent.question.disposition` on close to `answered`, `stored`, `declined` or the shared system closure code. Do not use a free-text reason. A late answer uses the answer operation (`modular_agent.question.answer` if there is no enclosing span), not the earlier ended span. Do not record question text or answers in these events. |
| History commit | `modular_agent.history.commit` | Child of the operation writing the history. Set `modular_agent.history.entry.count` to the batch size and `modular_agent.history.commit.status` to `committed`, `failed` or `uncertain`. End when the write is confirmed, fails, or cannot be resolved. Never include record bodies. |
| Lease renewal | `modular_agent.history.lease.renew` | Child of the operation on whose behalf it runs, if known; otherwise a separate span with the conversation ID. Do not attach it to whatever turn happens to be active. No lease token. |
| Capacity wait | `modular_agent.capacity.wait` | Child of the operation that waits. Set `modular_agent.capacity.scope` to `session`, `tenant` or `agent` if known. A refusal without a wait is an event `modular_agent.capacity.refused` on that operation. |
| Plugin in another process | `modular_agent.plugin.request` | One client span per work request; a participating plugin can record the server span. Use `modular_agent.plugin.name` and `modular_agent.plugin.method`, not request contents or raw paths. Inject the client context. This span describes the wire call, not a second model attempt or tool execution. |

When applicable, include the pinned convention's required attributes that are available and safe. Use a configured, low-cardinality `gen_ai.agent.name` where the convention calls for it. If the requested model is unknown, use the operation name without a suffix. For a Provider with no vendor mapping, use the name of the system the adapter reaches, or its registered Provider ID if that is all the Harness knows. Prefer recommended scalar attributes when known and safe. Record failed operations with OpenTelemetry error status and a bounded `error.type`, not a raw diagnostic. Track ordinary cancellations, limits and refusals by their dispositions. Do not emit `create_agent` for a local session or composition; it is a client operation to create a hosted agent. Use `invoke_agent` of kind `CLIENT` when calling another agent as an agent, for example beneath an `execute_tool` for an agent-backed tool. Use `plan` only for an explicit planning phase the Harness can observe, with the planning attempt beneath it. Do not infer it from reasoning content.

Record `gen_ai.client.inference.duration` in seconds once per model attempt, with the operation, Provider, model when known, and `error.type` on failures. Report known positive token usage with the `gen_ai.client.inference.usage.input_tokens` and `gen_ai.client.inference.usage.output_tokens` counters in `{token}`. Use the reported modality or `unknown`, and billable counts if available. Unknown usage is absent from the counters. Optional per-attempt distributions use `gen_ai.client.inference.operation.input_tokens` and `.output_tokens` with the upstream zero-for-missing-usage rule. Do not also emit the older generic inference metrics. Apply this accounting once at the Harness boundary, independent of trace sampling. Do not count history replay or add the same usage a second time at the turn or plugin boundary. Telemetry is not the usage ledger and does not promise exactly-once delivery across failures.

## Context on the wire

Senders MUST inject the current operation's W3C `traceparent` when it is valid and the destination is allowed to receive it. A peer MUST NOT treat it as identity, authority, session selection, a retry key or proof of sampling consent. Extract after authenticating the connection or HTTP request where required, and inside its scope. Invalid or absent context means no remote parent; telemetry metadata alone MUST NOT fail valid work. Incoming context from a peer outside the operator's trace trust scope MUST be ignored. Do not propagate across unrelated scopes. `tracestate` MAY accompany a valid parent for trusted peers, limited to operator-allowed vendor state. This profile MUST NOT send, accept into work context, or persist `baggage`.

| Boundary | Carrier |
|---|---|
| Plugin binding | Optional `params.traceContext: { traceparent, tracestate? }` on work requests and notifications, in either direction. Responses use the originating request's context locally; they do not carry the field. Send only to a peer that agreed to it in the handshake: the host offers `traceContext: 1` in `plugin/initialize`, and the plugin accepts by returning `traceContext: 1` in its registration. Either side omits the field when the other did not agree. A peer that does not know the member ignores the offer, so an existing `/1` plugin keeps working unchanged. `parentRequestId` and job/connection scope still govern callbacks. The Harness MUST keep a callback in its authorized operation's trace: use the callback context only if it has that trace ID, otherwise use the tracked parent or job context. Do not take context on unscoped credential reads or control messages. |
| ACP | W3C keys directly in `params._meta` on work requests (including `session/prompt` and agent-to-client questions where `_meta` is supported). Not in `_meta["modular-agent"]`. Use the context of the input that starts a turn, even if it waited in a queue; other queued or steering input MUST NOT change an already running turn's parent. Do not store ACP context in the public message or history view. Do not reuse context from `initialize` for later work. Trust the launcher of an operator-configured stdio Interface for trace context unless the operator turns that off. An authenticated network peer is trusted only if the operator configured it so; authentication alone does not grant it. Apply the same decision when injecting context into questions and permission requests. |
| History HTTP | Per request, use the HTTP `traceparent` header and optional `tracestate`. Include writes, reads and lease requests. A participating service extracts that request's context, not a value in a stored entry. |
| MCP | Use unprefixed `params._meta.traceparent` and optional `params._meta.tracestate` on MCP requests and notifications that take metadata, including `tools/call`, per [SEP-414](https://modelcontextprotocol.io/seps/414-request-meta). Do not substitute HTTP upgrade or request headers for message context. |
| WebSocket | Carry the plugin or ACP field in each JSON-RPC message as above. No connection-wide parent, custom frame or URL parameter. An upgrade trace, if used, describes only the upgrade. A reconnect does not determine a turn's trace. |

## Restart

For a durable turn, the Harness MUST commit the initial turn span's W3C context in `turnStart.data.traceContext` as `{ traceparent, tracestate? }` if it has a valid context for that span, including for an unsampled span. The `traceparent` identifies the turn span itself, not the incoming request's span. No baggage, content or exporter configuration is stored. Starting a trace is not permission to start a turn before the normal commit.

To resume, read the latest valid committed segment context for that turn. Start a new `invoke_agent` span with that context as parent and an explicit OpenTelemetry link to it. The parent keeps the trace ID; the link marks the interruption boundary. Keep the turn ID and assign a new span ID. Set `modular_agent.turn.resumed=true`. Commit the new context in a host-owned `modular-agent.turnTrace` checkpoint with the same `turnId`, `modelVisible: false` and `data.traceContext` before resuming effects. Another restart uses the last such checkpoint. Do not reopen or end the old span, invent a crash timestamp, or require the old span to have reached the exporter. If OpenTelemetry is a no-op, store no new segment context and retain the previous checkpoint. For an older turn without valid saved context, start a new trace when instrumentation is available and checkpoint that context. The recovered trace MUST NOT depend on the app keeping the same sampling policy. Telemetry metadata is never recovery authority.

Only use checkpoints for the interrupted, non-copied turn in its original session and trust scope. A Harness without this profile treats the checkpoint and the `turnStart` field as unknown data and keeps them: it can copy them into a fork or return them on a raw plugin history read. They hold only trace and span IDs, never content or authority; an operator who must keep those IDs private does not mix such Harnesses in one deployment. A fork MUST NOT inherit them. A [late-answer continuation](contracts.md#questions) starts a new turn with its own context, and links to the originating turn if available. Loading or resuming a session can initiate recovery but MUST NOT replace a recovered turn's saved parent.

## No content

Version 1 records no content. Telemetry MUST NOT include prompts, instructions, completion or reasoning text, tool definitions, arguments or results, question or answer bodies, history payloads, raw errors or arbitrary tags. Never record secret values, credentials, tokens, launch environment values or authorization headers. Apply this before the OpenTelemetry API, not just in an exporter filter, and do not enable raw capture in underlying instrumentation as a way around it. Span names use registered, vetted names only. Omit an unsafe suffix and never use request text as a fallback. Because no record content leaves through telemetry, the exporter is not a copy that erasure must report. Version 1 writes no disclosure markers.

## Conformance checks

The [shared SDK check](sdk/testing.md#shared-telemetry-check) receives each language's exports over OTLP/HTTP (protobuf) to compare them across languages. For local checks, use an in-memory exporter.

Install an OpenTelemetry SDK with an always-on test sampler. Use a scripted Provider, deterministic tools, fixture barriers and a controlled store. No collector or live model is needed. The check can assert:

- The declaration is independent of export. Without an SDK, work still settles. A failing exporter cannot change effects, commitments or outcomes.
- Parentage, kinds, names and attributes match the mapping. Include a failed attempt and retry, overlapping nested calls, a job, an open question, an uncertain commit, a lease renewal and a wait. A manual metric reader checks one duration measurement per attempt and no duplicate token accounting.
- Capture the operation context at plugin, ACP, history HTTP and MCP boundaries, including both carried bindings over WebSocket. Interleave unrelated work on one connection. Verify ignored malformed or untrusted context and no baggage propagation or change in authority.
- Kill a durable agent after a committed checkpoint, restart it, and observe the same trace ID and turn ID, a fresh span ID and the link to the saved segment. Repeat after a second committed resume checkpoint. A fixture persisting the observed first segment context outside the killed process can check this even when the first span was never exported. Check that a fork and a legacy turn do not adopt the saved context.
- Search every exported span, attribute and event for fixture payloads and secrets; none may appear.
- Over the plugin binding, check the field is sent only after both sides agreed in the handshake, and that a plugin which did not agree receives none.

## What later versions add

Tracing is meant to grow. Each addition is a new profile version, declared as `telemetry: 2` and so on, with its own checks:

- **Content capture.** Opt-in, through the [output gate](contracts.md#the-output-gate) with telemetry as its own recipient, with secrets removed. Before content reaches OpenTelemetry the Harness records a content-free disclosure marker, so a later erasure can report the exporter as `outOfReach`, coordinated across writers as for any other disclosure. ADR 0032 records the design.
- **Streaming detail.** Span events for model output and tool progress as they arrive, without their content unless capture is on.
- **Metrics beyond inference.** Tool, turn, queue and capacity measures, and cost where the Provider reports it.
- **Traces across agents.** Links between a host's work, subagents and peers, so a trace follows work from one whole agent into another.
- **Logs.** Correlated log records for the Harness's own warnings and refusals.
