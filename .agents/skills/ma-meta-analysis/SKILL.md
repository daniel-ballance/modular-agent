# Audit ma sessions

1. Pick the languages, sessions and time window to compare. Read complete JSONL records in place under `~/.local/state/modular-agent/<lang>/history/`, where `<lang>` is `rust` or `typescript`. Use the [state folder overrides](../../../docs/reference/standard-configuration.md#files) if the launch used them. Leave partial trailing records for the next pass. Keep histories and Phoenix data read-only. Never read `auth.json` or log secrets or credentials. Report counts, timings and redacted evidence. Keep raw messages, scripts, tool inputs and outputs out of the report.
2. Read spans for the same window from `http://127.0.0.1:6006/v1/projects/default/spans` with a GET request. Follow the pagination cursor through the window. Match `gen_ai.conversation.id` to the session and use `modular_agent.turn.id` and `modular_agent.step.id` within it. Use the Provider on each model request or `modular_agent.provider.id` on its span, since a session can switch Providers. Record missing trace coverage, such as sessions recorded before export was enabled. See [Evaluating ma on real work](../../../CONTRIBUTING.md#evaluating-ma-on-real-work) for export setup.
3. Count distinct turns and steps per turn from the history IDs. Count incomplete turns separately. Count committed compactions from summary records and measure auxiliary attempts separately from ordinary steps. Use `invoke_agent` spans for turn wall time, model attempt spans for model time and `execute_tool` spans for tool time. Use unions of intervals within each turn to avoid counting a script and its nested calls twice or summing parallel calls as serial time. Report overlap between model and tool intervals if present. Mark history timestamps as estimates when spans are absent and leave unknown intervals unmeasured.
4. Sum the disjoint `input`, `cacheRead`, `cacheWrite` and `output` fields once per metered identity. Include auxiliary usage when recorded. Exclude copied history, replay and turn totals from the sum. Treat absent usage as unreported. Compare matched model attempts against Phoenix using the [token mapping](../../../docs/telemetry.md#token-counts): `gen_ai.usage.input_tokens = input + cacheRead + cacheWrite`. Compare the output and both cache fields too. Calculate cache hit rate as `cacheRead / (input + cacheRead + cacheWrite)` from the summed counts when the denominator is positive. Check mismatches for unmatched attempts, retries, recovery and sampling before treating them as accounting errors.
5. Join `codemode` calls and their descendants by parent call ID. Report nested calls per script, including zero-call scripts, and the failed share of settled scripts. Give refused and cancelled counts separately. Count truncation hits from `exec`'s `truncated` flag and `codemode` output cut notices. Measure check-wait time from calls that block the turn while waiting for checks, including time waiting for a check slot when identifiable. Count overlapping waits once and distinguish time spent waiting for a slot from check execution where the evidence gives both.
6. Report these measures per session and per Provider with the sample sizes and missing coverage. Attribute turn and tool measures to the associated Provider when the records identify it. Search open issues for each reproducible problem a real run can hit. Comment on a match or file an issue with `finding`, the starting `layer:` label and each affected `lang:` label. Use the current milestone only when its “Done when” needs the issue, otherwise use the next one.
