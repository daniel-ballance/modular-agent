# Changelog

The four SDKs share one version, the revision of the [SDK specification](docs/sdk/README.md). Nothing is published to a registry; a version names a commit on `main`.

## Unreleased

- **Subscription Providers in all four SDKs ([ADR 0031](docs/adr/0031-subscription-providers.md)).** `chatgpt()` signs in to a ChatGPT plan through OAuth and keeps the login in a shared, locked login file (`subscriptionLogins`, `signIn`, `signOut`). `claude()` uses the Claude Code sign-in through Anthropic's Agent SDK and never handles a Claude credential; Rust and Go start the TypeScript Claude program, which needs Node.js 22 or later. `ma` now uses them. Its Provider ids are `chatgpt` (was `openai-codex`) and `grok` (was `xai`). The former ids still work everywhere, and a stored login moves to the new id the next time `ma` writes `auth.json`. Grok is not yet an SDK Provider: [the research](docs/research/grok-x-subscription.md) found no xAI sign-in for other programs, so `ma` keeps its existing Grok code. Real requests through ChatGPT, Claude and Grok succeeded in all four `ma` builds.
- **`ma` names itself `modular-agent`** to ChatGPT and Grok, instead of Pi's `pi`. Set another name with `MA_CLIENT_IDENTITY`, or with the ChatGPT and Grok Providers' client identity option in code. Real requests through all four `ma` builds succeeded with the new name; sign-in sends it too.
- **macOS, checked on Apple silicon.** All four SDKs and `ma` builds pass their test suites, the reference checks and the ACP kit on macOS (`scripts/macos-check.sh`). HTTP history needs no clock setting there: Rust, Go and Python read `CLOCK_MONOTONIC`, which counts through sleep, and TypeScript derives a sleep-aware clock (allowed by the [history binding](docs/bindings/history-http.md#writing-one-writer-at-a-time)).
- **Fixed intermittent failures:** a Go history service held renewals behind unrelated disk writes, so a busy writer lost its lease; Python ACP replaced a held-lease refusal with `forbidden` on reopen. Kit checks that failed once without a found cause now report what they saw.
- **Production gaps closed ([ADR 0030](docs/adr/0030-production-gaps.md)).** Per-connection isolation, capacity reserved so settlement always completes under load, and cross-session erasure coordination, in all four SDKs and `ma`, with `ma`'s operator `policy.json`. New opt-in kit checks for each, run by `scripts/production-kits.sh` in `scripts/check.sh`. Erasure is coordinated through one interoperable history profile, `pendingErasure: 1`, which every language's history service and client implement: each language's agents pass the erasure checks on every language's history service.
- Specified the optional [pending-erasure registry for history HTTP](docs/bindings/history-http.md#pending-erasure-registry-profile-pendingerasure-1), so agents can share pending marks and reconcile them under current writer leases.
- Added the [project notes demo](demos/project-notes/README.md): one agent using all four SDKs, with a scripted check for normal execution and crash recovery.

- **One codemode in all four `ma` builds.** Go dropped gomonty (Monty 0.0.9) and drives the pinned Monty 1.6.0 worker over its protocol; the worker is built with Go `ma` and never downloaded at run time ([research](docs/research/codemode-engines.md)). The [Tools section](docs/reference/standard-configuration.md#tools) now fixes one exact profile: `import tools` and tool functions as values, alphabetical positional order for optional fields, how a value, an error and the print limit are rendered, the compute clock totalled across pauses and reset only by a tool call, and no wall clock, sleep or system entropy. Five new reference checks; all four builds pass 23 of 23.

- **Session interrupted, a new standard event.** When an agent stops writing a session because a commit failed or it lost writer access, it now tells everyone following the session, and a caller waiting on the session fails with `lost`. Before, it stopped silently, and a client following events waited forever.
- **Specified [ADR 0029](docs/adr/0029-sdk-decisions-after-four-builds.md):** ACP service liveness and token scope, rejection of persistent history under `ephemeral`, scoped model requests from commands, and a shared API-key model table.
- **SDK options for several actors, session limits and tenants,** off unless chosen, and app-side questions: list the waiting ones, answer later, decline as distinct from text. In all four SDKs.
- **Crash-safe secrets.** A secret answer is staged, then selected, then activated, so a crash at any point leaves the old value or the new one. In the SDKs' file credential stores and `ma`'s `auth.json`.
- **Developer Providers** report catalog changes and readiness, in process and served over the plugin binding.
- **Six more shared scenarios** (`question-answered-later`, `decline-is-not-text`, `actor-rights`, and three for `ephemeral`), and a WebSocket service placement for each SDK: 17 scenarios in 9 placements, 612 runs, all passed.
- **The SDK specification revised from four builds:** 22 findings applied and 30 rejected ([findings](docs/research/sdk-findings.md)), then the gaps each SDK still listed closed: custom parts through the Registrar, changing tool sources, job owners with recovery, typed hooks and events, commands that ask or call a model, proposals, Content input and progress, and one shared table of API-key models and their reasoning levels.
- **WebSocket transport** for the plugin and ACP bindings ([ADR 0028](docs/adr/0028-websocket-transport.md)), in all four SDKs: `serve` with `listen`, `servicePlugins`, `serveAcp` with `listen`, and `ma --acp --listen`. The plugin and ACP kits check a service with `--connect`; `scripts/check.sh` runs both against each language's own servers. The shared scenarios gain a service placement for each SDK: 504 runs, all passed.
- **Live checks** pass against OpenAI and Anthropic in all four SDKs.
- **`ma`'s code sandbox runs in a worker process** with a 256 MiB memory limit, in all four languages. A limit that fires, or a worker that dies, fails that run and the agent carries on; a new reference check, `sandbox-memory`, checks it. Go's served environment now lists directories.
- **Fixed in all four SDKs:** a new session wrote its setup to persistent history before its first input; a plugin host could deadlock, or deliver progress out of order, when a plugin's own hook answered a callback; a served command used the wrong project (it now asks `host/session`).
- **Fixed:** the TypeScript local environment could lose its record of running commands if the agent was killed while saving it, leaving those commands running. Python `ma` now shows codemode calls on stderr instead of `tool(null)`.

## 0.1.0

The first version for developers to try, on Linux.

- **Specification.** [Edition 4](docs/adr/0027-sdk-0-1-and-edition-4.md) replaces production edition 3: nested tool calls, `modelTools`, directory listing, a nested call's parent over ACP, and three Provider clarifications. The ACP kit now also checks that an agent refuses the features it declares off.
- **SDK specification 0.1,** accepted: the Agent and sessions, typed tools, plugins that run in process or in another process unchanged, durability (`ephemeral`, `kept`, `durable`), questions, hooks, Providers, ACP, history over HTTP, and a testing kit with a scripted model ([`docs/sdk/`](docs/sdk/README.md)).
- **SDKs in Rust, TypeScript, Go and Python,** each wrapping that language's clean-room build. Each passes the eleven shared scenarios in process and with the test plugins served by every SDK: 220 runs.
- **Guides 01 to 09,** each with its examples running as tests in all four languages.
- **`ma`, the standard configuration,** in all four languages: one `codemode` tool on Monty, the six file tools, MCP, Agent Skills, ChatGPT, Grok and Claude subscription Providers, a terminal and ACP. All four pass the fifteen reference checks and the identical 188 ACP kit checks.
- **Repository.** MIT license; `scripts/check.sh` runs every check locally; [CONTRIBUTING.md](CONTRIBUTING.md).

Known gaps are listed in the [README](README.md#known-gaps) and each SDK's README.
