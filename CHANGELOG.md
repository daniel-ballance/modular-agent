# Changelog

The four SDKs and `ma` share one project version. The [SDK specification](docs/sdk/README.md) has its own revision. Nothing is published to a registry; a version names a commit on `main`.

## 0.3.0

The third release, on Linux and macOS. Approvals can wait past their turn and cover a whole script, `ma` gains an approval setting, a host can learn why a wait closed and how a lost run ended, and code kept only for earlier versions of this project is gone. Results are in [docs/status.md](docs/status.md#030).

- **Approvals that wait past their turn ([ADR 0034](docs/adr/0034-approvals-that-wait.md)), in all four SDKs.** With an operator maximum (`maxApprovalWaitMs`) and a session that opts in (`approvalWait: "untilDeadline"`), a model's call to a server tool that needs approval ends the turn unstarted, so the agent's process can stop. An approver who returns later is shown the exact call and answers on that route; one continuation then rechecks consent, rights, registration, input and the deadline before the call runs, and refuses a call that changed. The ACP and AG-UI kits, the shared scenarios (28 more, run only for agents that declare the feature) and the telemetry check cover it.
- **Approvals that cover nested calls** (an [ADR 0034 amendment](docs/adr/0034-approvals-that-wait.md#amendment-approvals-that-cover-nested-calls)), in all four SDKs. With the operator option `approvalCoversNested`, an explicit allow for a top-level call also answers the approval check of each nested call it makes in that dispatch. Every other check still applies, the approval view says the allow covers nested calls, and each covered call's `toolStarted` records `approvalCoveredBy`.
- **Approval in `ma`**, off by default: `--approval POLICY` or the global `approval` setting. A `codemode` script is approved as a whole and its writes and commands run under that allow. The terminal asks `y`/`n`; print mode refuses. Approvals wait past the turn only with `approvalWaitMaxMs` in `policy.json` and `approval_wait: "untilDeadline"`. ACP and AG-UI clients with the `settings` right can change the policy per session; AG-UI gains `POST /agui/v1/threads/{threadId}/settings` for this. A 28th reference check, `approval-covers-script`, passes in all four builds.
- **Fixed:** Rust's rewind treated a call settled in a continuation turn as unfinished.
- **What a host can learn from one agent ([ADR 0035](docs/adr/0035-host-limits-from-the-ops-desk.md)), in all four SDKs and `ma --agui`.**
  - A [wait-closure feed](docs/bindings/agui.md#wait-closures) per AG-UI thread: from the snapshot's `waitCursor`, each question or client tool wait that closed, in commit order, with its committed reason. It is gated per viewer, is not presence and cannot answer.
  - [Run receipts](docs/bindings/agui.md#run-receipts) for kept sessions: `{ terminal, work }` for a run ID, so a host can learn how a lost AG-UI run ended (`unknown` if the agent died before recording its end) and how its work settled. No content, no replay.
  - [Named callers](docs/bindings/websocket.md#named-callers) on one plugin listener: an operator table of token files and caller IDs; each connection gets a fresh plugin instance that is told the authenticated ID.
  - The AG-UI kit has 48 cases (14 new) and the plugin kit a named-callers transcript.
- **Fixed:** the ops desk station could hand a `start` the address of an agent process that was still stopping.
- **Fixed:** in TypeScript, a shell command could start before its cleanup watcher was registered, so a `kill -9` at that moment could leave it running.
- **AG-UI approval interrupts carry `metadata["modular-agent.approvalCall"]`** (`{ name, input }`, the exact gated call), so a client can show the call without parsing the prompt. Required; the ops desk renders the coder's script from it.
- **No backward compatibility before 1.0** ([CONTRIBUTING](CONTRIBUTING.md)). Removed, in the spec, kits and all four SDKs and `ma`:
  - the `openai-codex` and `xai` provider IDs, their login migration and saved-session translation (use `chatgpt` and `grok`);
  - legacy history associations (only envelope `inputId`, `requestId`, `continuesTurnId`), pre-atomic job-report repair, old replay records, missing-authority defaults, sourceless fork prefixes, the old actor kind and failed-position records;
  - the plugin trace-context handshake (context rides on each operation) and the plugin binding's separate data selector;
  - Rust's and Python's pre-binding ACP dispatchers, the TypeScript Claude sidecar wrapper, start-up migrations of erasure registries, fallback credential files, guessed lease intervals, and `MA_HOME`.
  Old private state is refused, not converted. Kit cases that skipped when a feature was absent now fail; every build's fixtures declare every feature.
- **Fixed, found by the stricter kits:** TypeScript and Go re-showed a waiting approval that the output gate had hidden; Go placed a late tool result after a newer user message in the model context; Rust answered `invalid_params` instead of `busy` for erase, move and fork during a turn; Rust's conformance model read the turn's history instead of the request; Rust answered `lost` when a plugin call was cancelled while its environment callback was open; Python's history service promoted nested IDs into erasure tombstones.
- **Fixed on macOS:** the kits, scenario runners and ops desk treated `EPERM` from signalling a process group that still held a zombie as an error; Python's history service listened with a backlog of 5, so several simultaneous connections were reset.
- **`ma --version`** prints `ma VERSION (LANGUAGE)` with the language in lowercase in all four builds.

## 0.2.0

The second release, on Linux and macOS. It serves agents to web apps over AG-UI, lets a client run tools, traces every agent with OpenTelemetry, and adds a demonstration host that drives three agents.

- **AG-UI and tools run by a client ([ADR 0033](docs/adr/0033-interface-tools-and-ag-ui.md)).** A new binding, `modular-agent-agui/1`, serves an agent to a web app over AG-UI 1.0 (HTTP and server-sent events), beside ACP on the same listener: `serveAgui` in every SDK and `ma --agui --listen ADDR`. Tools can be run by a connected client's Interface: the call passes every check, is recorded as handed off, stays open across runs and reconnects without ever running twice, and settles as outcome unknown if no result arrives before its deadline. Stock AG-UI clients work for conversations and client tools; approvals need the optional presence stream. A new kit, `conformance/agui/`, now has 26 cases including thread listing.
- **Finding open work after a restart.** AG-UI's `GET /agui/v1/threads` lists the threads a client may watch, with how many questions and client tool calls wait for it and whether a turn is running or interrupted; ACP's `session/list` can carry the same summary. `ma --resume-open` (or the global setting `resume_open`, off by default) reopens interrupted sessions at start-up so durable turns carry on without a client. The `resume-open` reference check covers this.
- **OpenTelemetry tracing in all four SDKs and `ma`** ([ADR 0032](docs/adr/0032-telemetry.md), [profile](docs/telemetry.md), declared as `telemetry: 1`). The Harness records spans for turns, steps, model attempts, tool calls, jobs, questions, history commits, lease renewals and capacity waits, following the OpenTelemetry GenAI conventions, through each language's OpenTelemetry API; nothing is exported until an app installs an exporter. Trace context crosses plugins in other processes (once both sides agree in the handshake), ACP, history HTTP and MCP, and a durable turn resumed after a crash continues its trace. Version 1 records no content. `ma` exports through the standard `OTEL_*` variables, off unless an endpoint is set. A shared check, `conformance/telemetry/`, receives each language's real exports and compares them with the profile: 104 cases across the four languages as hosts and plugins, all passed. `scripts/phoenix.sh` starts a local Arize Phoenix to look at traces.
- **`gen_ai.usage.input_tokens` includes cached input,** as the GenAI conventions require, with cache reads and writes also reported apart. A model reply with no `usage` now means unreported, not zero. A new reference check, `telemetry-export`, checks how `ma` exports. The suite now has 28 checks, including `approval-covers-script` and `trace-trust` for the operator's per-connection trace policy.
- **The ops desk demo** (`demos/ops-desk`): a TypeScript host drives three agents over AG-UI (Python triage, Rust `ma` coder, Go verifier) with one conversation, one inbox for approvals and a webhook listener. Six scripted checks run in `scripts/check.sh`, including a host killed while an approval waits; `run.py --live` runs it on your subscriptions.
- **Held output is never silently shortened.** In all four SDKs a held model or tool stream reaches its gate in segments of at most 4 MiB, and a piece that cannot fit blocks the stream instead of being dropped. An Interface tool result reported before its turn ends is refused with the reason `notReady` in every SDK. Go ties AG-UI approvals to the client holding presence; Rust link questions carry their address; a client waiting on a continuation that cannot get a turn is told `busy`. Python `ma` starts faster by loading ACP, MCP transports and Claude only when used.
- **The first Claude request is quick.** The Claude program reported readiness only after reading every model's context window, which took about 12 s; it now answers once Claude Code confirms the account. Rust asks the program, as Go does, instead of running `claude auth status`. Python no longer starts Claude Code every minute to recheck. An unavailable Claude reports why over the plugin binding.
- **The history service's writer lease is 15 seconds by default,** set with `leaseTtl` in every SDK. The TypeScript services refuse settings they do not recognise.
- **Faster local checks.** `scripts/check.sh` runs each language in its own lane: the full run takes about 35 minutes instead of 79, `--quick` about 8 instead of 11, the erasure matrix 3 instead of 17. `--serial` keeps the old order. Each step has a 30-minute hang guard. `scripts/stress.sh N` repeats the check and lists every failure.
- **Fixed, found under load:** Rust and Python reported a turn as ended before the session was idle, so a fork or a setting changed straight after `prompt` could be refused. A Rust ACP driver could hold the erasure guard while idle. In Go, a history write in flight kept the old deadline after its lease was renewed, and a command's buffered output could be lost when it exited.
- **`ma` can trust a host's trace,** with `traceTrusted` in its operator policy (true for stdio, false for network clients by default), so one event's trace runs through every agent a host drives. A new reference check, `trace-trust` (28 checks in the current suite).
- **Python's plugin traffic no longer grows with session length:** one tool turn on a 1,000-entry session with plugins in other processes exchanged 23 MB; it now exchanges 0.85 MB.
- **Specified, implemented in 0.3.0:** [approvals that wait past their turn](docs/adr/0034-approvals-that-wait.md) (ADR 0034).
- **Fixed:** Rust refused `allow` for a tool's approval that listed no options.

## 0.1.0

The first release, for developers to try, on Linux and on macOS (Apple silicon). Nothing is published to a package registry; build from this tag.

- **Specification, [edition 4](docs/adr/0027-sdk-0-1-and-edition-4.md):** nested tool calls, `modelTools`, directory listing and a nested call's parent over ACP. Since edition 3 it also gained the WebSocket transport for the plugin and ACP bindings ([ADR 0028](docs/adr/0028-websocket-transport.md)), a `sessionInterrupted` event when an agent stops writing a session, ACP service liveness and token scope ([ADR 0029](docs/adr/0029-sdk-decisions-after-four-builds.md)), and the production rules of [ADR 0030](docs/adr/0030-production-gaps.md): per-connection isolation, reserved capacity so settlement completes under load, and cross-session erasure through the [`pendingErasure: 1` history profile](docs/bindings/history-http.md#pending-erasure-registry-profile-pendingerasure-1).
- **[SDK specification](docs/sdk/README.md) 0.1:** the Agent and sessions, typed tools, plugins that run in process or in another process unchanged, durability (`ephemeral`, `kept`, `durable`), questions that can be answered later, typed hooks and events, commands, jobs with owners and recovery, options for several actors, session limits and tenants, Providers, ACP, history over HTTP, and a testing kit with a scripted model. It was revised after four builds: 22 findings applied, 30 rejected ([findings](docs/research/sdk-findings.md)).
- **SDKs in Rust, TypeScript, Go and Python.** Each passes 17 shared scenarios in process and with the test plugins served by every SDK, over stdio and WebSocket: 612 runs. Live checks pass against OpenAI and Anthropic.
- **Subscription Providers in every SDK ([ADR 0031](docs/adr/0031-subscription-providers.md)):** `chatgpt()`, `grok()` and `claude()` use a person's own plan. ChatGPT and Grok sign in through OAuth and keep their logins in a shared login file, locked across processes and languages. `claude()` uses the Claude Code sign-in through Anthropic's Agent SDK and never handles a Claude credential; Rust and Go start the TypeScript Claude program, which needs Node.js 22 or later. ChatGPT and Grok sign in with the vendors' own coding tools' OAuth clients ([Terms of use](docs/sdk/subscription-providers.md#terms-of-use)).
- **Guides 01 to 09,** each with its examples running as tests in all four languages.
- **`ma`, the standard configuration,** in all four languages: one `codemode` tool on Monty 1.6.0 with one exact profile, run in a worker process with a 256 MiB limit; the six file tools; MCP; Agent Skills; the ChatGPT, Grok and Claude Providers; rewind points kept as commits in the project's git repository; an operator `policy.json`; a terminal; and ACP on stdio or a WebSocket. It names itself `modular-agent` to ChatGPT and Grok (`MA_CLIENT_IDENTITY` changes it). All four builds pass the 24 reference checks and the identical 188 ACP kit checks.
- **[Project notes demo](demos/project-notes/README.md):** one agent made of parts in all four languages, with a scripted check of normal running and crash recovery.
- **Repository.** MIT license. `scripts/check.sh` runs every check locally; `scripts/macos-check.sh` runs the suites on a Mac. [CONTRIBUTING.md](CONTRIBUTING.md).

Known gaps are listed in the [README](README.md#known-gaps) and each SDK's README.
