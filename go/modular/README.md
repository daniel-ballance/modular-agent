# modular: the Go SDK

This is the Go implementation of [SDK 0.1](../../docs/sdk/README.md). It wraps the edition 4 Go build. Application and plugin code uses the `modular` package, not the base Harness or its API.

```go
agent := modulartest.Agent(t, modulartest.Script(`[{"text":"Hello."}]`))
session, err := agent.Session(t.Context())
if err != nil {
    t.Fatal(err)
}
turn, err := session.Prompt(t.Context(), "Say hello.")
if err != nil || turn.Text != "Hello." {
    t.Fatalf("turn: %+v; error: %v", turn, err)
}
```

Import `github.com/daniel-ballance/modular-agent/go/modular/modulartest` for tests and `github.com/daniel-ballance/modular-agent/go/modular` for applications. The SDK uses `github.com/google/jsonschema-go` for tool schemas and [Gorilla WebSocket v1.5.3](https://pkg.go.dev/github.com/gorilla/websocket@v1.5.3) for the network binding. The same plugin and ACP handlers serve stdio and WebSocket connections.

## Official file and MCP tools

- `modular/files.Plugin(spill)` registers the six standard file and command tools. It uses `ToolContext.Environment`, which scopes file and command operations to the current call and works both in process and through the plugin binding.
- `modular/mcp.WithServers(servers, warn)` connects trusted MCP servers. A warning handler opts into skipping failed configured servers, while client-supplied ACP attachments remain scoped to their session.
- `NewSchemaTool` accepts an explicit JSON Schema object. `OnSessionPrepare` installs per-session resources before recovery. The in-process `OnTurnBefore` payload includes the canonical project and plugin-callable tool definitions; inspecting them does not grant authority.
- `Agent.Sessions` and `Agent.SessionInfo` read stored metadata without opening a session. Both are available on `HistoryStore` before composition. `Session.Busy` and `Session.WaitIdle` let a terminal distinguish active work from an idle session.
- `SessionInfo.UnfinishedTurn` means a committed turn start has no end. It does not say the writer is free. `Agent.ResumeInterrupted(ctx, id, operator)` checks the recorded watch right in the configured project, tries the writer without waiting, and checks the turn again under the lease. It returns after installing ordinary recovery, not after the turn ends.
- `Agent.ServeACP` takes `ServeACPOptions` with `Compose`, `ProjectSettings`, and `ProjectMCP` to serve several canonical projects on one connection. `WithCompaction` controls automatic context compaction and `/compact`.
- `WithLateAnswersStartTurns` lets enabled tools leave a question open after a wait with `AskOptions{Then: "leaveOpen"}`. `WithJobReportsStartTurns` lets job reports start turns; otherwise the reports are parked.

The [Go `ma` README](../cmd/ma/README.md) shows these parts composed and tested as the standard configuration.

## Subscription Providers

Import `github.com/daniel-ballance/modular-agent/go/modular/subscription`.

- `subscription.SubscriptionLogins(path)` names a private JSON login file. Writes preserve other members, replace the file atomically and use a sibling `.lock` shared with other processes. The same lock covers token refresh.
- `subscription.SignIn(ctx, "chatgpt", logins, subscription.SignInOptions{...})` stores a login and reports `OpenAndPaste`, `DeviceCode` and `Waiting` through `OnStep`. Supply `Paste` to read input, or set `Device: true` for a device code. Use `"grok"` in place of `"chatgpt"` for a Grok device sign-in. Grok ignores `Device` and `Paste` and reports only `DeviceCode` then `Waiting`. The SDK does not open a browser. `subscription.SignOut(ctx, id, logins)` removes the login for either id.
- `subscription.ChatGPT(subscription.ChatGPTOptions{Logins: logins})` and `subscription.Grok(subscription.GrokOptions{Logins: logins})` each return a `modular.Provider` and an error. Use `modular.WithProvider` to register them. Set `Models` to enroll unlisted ids.
- `ClientIdentity` is a pointer to a string on both constructors and on sign-in. Nil uses `modular-agent`. An explicit label must be 1 to 64 ASCII letters, digits, dots, underscores or hyphens. `subscription.ValidateClientIdentity(label)` checks an explicit label. Grok sends the label as `referrer` only when starting sign-in.
- `subscription.Claude(ctx, subscription.ClaudeOptions{Program: path})` starts the TypeScript Claude program with Node.js 22 or later. Register `modular.WithPlugin(claude.Plugin())` to close the child with the agent, or use `claude.Provider()` and call `claude.Close()` yourself. `claude.Status(ctx)` reports readiness and the reason when unavailable. Go does not sign in or touch Claude credentials; use `claude auth login`.
- For an API-key account, the current Claude program reports the source of the key through `provider/available`. A legacy program that reports only the boolean cannot give that detail.
- Claude resolves `Program` first, then `MODULAR_AGENT_CLAUDE_SIDECAR`. If both are unset it looks for `typescript/sidecars/claude/dist/main.js` relative to the executable or up to three directories above it, then `~/.local/share/modular-agent/sidecars/claude/dist/main.js`. Set the path explicitly if using the TypeScript SDK's program from another install location.

## Checks

From the repository root:

```sh
npm ci --prefix conformance/acp
npm ci --prefix conformance/tools
npm ci --prefix conformance/telemetry
# Build the four fixture programs per conformance/sdk/fixtures/*.json.
(cd go && ./scripts/build-monty.sh)
export MODULAR_AGENT_SDK_REQUIRE=all
(cd go && mise exec -- go build ./... && mise exec -- go vet ./... && test -z "$(mise exec -- gofmt -l .)")
(cd go && mise exec -- go test -count=1 ./...)
(cd go && mise exec -- go test -race -count=1 ./modular/... ./cmd/ma/...)
(cd go && ./scripts/build-monty.sh && mise exec -- go build -o .bin/ma ./cmd/ma && mise exec -- go build -o .bin/modular ./cmd/modular && mise exec -- go build -o .bin/modular-agent-fixtures ./modular/cmd/fixtures)
node conformance/reference/run.mjs --agent go
ma="$PWD/go/.bin/ma"
(cd conformance/acp && MODULAR_AGENT_CONFORMANCE=1 node run.mjs --crash-checks --probe-checks --job-checks -- "$ma" --acp)
scripts/websocket-kits.sh go
go/scripts/check-agui.sh
```

On Linux, the base suites need unprivileged user, PID and mount namespaces. On macOS, the local working environment declares `processGroup` containment. The suite checks that scope rather than requiring cleanup of descendants that leave their process group. The history writer uses `CLOCK_BOOTTIME` on Linux and `CLOCK_MONOTONIC` on macOS. Both clocks advance during sleep, so neither platform needs a lease margin.

The scenario runner builds Go's fixture and discovers built peer programs. Build each peer with its [fixture registry](../../conformance/sdk/fixtures/) command. `MODULAR_AGENT_SDK_REQUIRE=all` requires all four programs and runs the whole matrix.

### Approvals that cover nested calls

`modular.WithApprovalCoversNested(true)` is a composition option, not a session setting. With the approval plugin it declares `approvalCoversNested: true`; otherwise the key is absent. Show `Question.Call`, including the complete input, and tell the approver when `Question.CoversNested` is true. ACP carries `coversNested` on the request and in the permission RPC metadata. AG-UI carries `metadata["modular-agent.coversNested"]` on the interrupt.

An explicit allow answers the approval check for the nested calls this top-level call makes, at any depth in that dispatch. Each covered start records `data.approvalCoveredBy: { toolCallId, requestId }` in history. Rights, other gates, input validation, registration, the nesting limit and final dispatch checks still apply. An unasked parent grants no coverage. `never` still refuses. Repeating a live dispatch requires another allow. For a waiting call the original request decides the scope: enabling coverage on reopen cannot widen an unmarked view.

### Approvals that wait

Set `SessionOptions{Settings: modular.Settings{"approvalWait": "untilDeadline"}}` at creation or call `s.SetSetting(ctx, "approvalWait", "untilDeadline")`. The default is `"live"`. The declaration key `approvalsOutlastTurns` reports support, not consent. Only the pre-dispatch gate on a top-level model call to a server tool can park it. Direct, nested and Interface calls do not change.

After the origin prompt returns, the call is in `PromptResult.OpenToolCalls`. No result is available yet. To decide on an open handle:

```go
qs, err := s.Questions(ctx, modular.QuestionsOptions{Present: true})
if err != nil { return err }
for _, q := range qs {
    if q.ApprovalWait == "untilDeadline" && operatorAllows(q.Question, q.Call, q.Deadline) {
        return s.Answer(ctx, q.ID, modular.Allow())
    }
}
```

`operatorAllows` stands for the application showing the full question, name, input and deadline and getting the operator’s decision. A plain `Questions(ctx)` does not establish delivery. Keep the answering handle, including the one returned by `s.As(actorID)`. After reopen, poll again. An allow closes the request; a continuation still checks whether the original call can run. ACP uses `requests` and `answer` on the same connection, not a permission RPC. In AG-UI, open presence on return, fetch the thread snapshot and answer its interrupt with `resume`. Neither an inbox row nor a snapshot authorizes client-side execution. The operator can configure [approval in `ma`](../cmd/ma/README.md#approval).

### History service leases

Set `modular.HistoryOptions.LeaseTTL` when calling `modular.ServeHistory` to choose the writer lease. Zero uses 15 seconds. A nonzero `time.Duration` must be a whole number of milliseconds and at least 1 ms, or the call returns `invalid_params`. The service declares the duration as `ttlMs`. An HTTP relay uses the upstream service's declaration and does not issue its own leases.

### HTTP pending erasure

The dedicated file history service declares `pendingErasure: 1`. It keeps both pending and completed plans in `.history-erasure-v1`. Leases end on restart; the new writer reads the plans, reuses the reserved bookkeeping ID and verifies physical tombstones before completing a plan. A missing or unreadable registry makes coordinated requests unavailable. Restore history and registry together and prove freshness against an independent authority before serving either.

The old `/go/pending-erasure` route and `goErasureGuard` append member are removed. No in-repository client still needs them. Do not replace a legacy registry with an empty one. Existing deployments must fence old writers, settle their pending work, and migrate offline before enabling the new profile. A native snapshot-store listener does not declare the profile because native writers do not share its HTTP transaction lock. An authenticated HTTP relay preserves the upstream declaration and revision header.

A repeated publication returns the original intent ID and destinations in published order. The source has its own plan and is not in the destination list. The client uses that list to find plans even when a peer expires a destination. Expiry is not proof of erasure. The report marks copies in expired sessions as out of reach without exposing their IDs.

### WebSocket services

- `modular.ServeService(ctx, plugin, modular.ServeOptions{Listen: "127.0.0.1:0", TokenFile: path})` returns a `Service` with `URL`, `Done()` and `Close()`. `Setup` runs per connection; put mutable instance state inside it or use `ServeServiceFactory` if the `Stop` closure also needs that state. A service environment requires `ServeOptions.Projects`, a list of operator-approved canonical projects, and checks requested file paths under the initialized project. With a single token, use this listener for only one host trust scope. Use separate process and filesystem confinement where a plugin or shell could reach another scope. Configuration paths such as the counter fixture's `path` are interpreted by trusted plugin code, not remapped by the SDK.
- `modular.WithServicePlugin(modular.ServicePlugin{URL: svc.URL, TokenFile: path, Config: config})` dials the service using system TLS roots. Plain WebSocket dials and listeners are loopback-only. `TLSOptions{CertFile: cert, KeyFile: key}` enables WSS at the listener. Generate a bearer token with at least 128 bits of entropy and put it in an owner-only file. The operator can set `PingInterval` and `ControlDeadline` for an explicit service plugin.
- `agent.ServeACP(ctx, modular.ServeACPOptions{Listen: addr, Actors: entries})` blocks until stopped. `agent.ListenACP` returns the `Service` as soon as it listens. Each `ACPActor` supplies `TokenFile`, `Actor`, `Projects`, `Tenants`, and optional `Represents`. For stdio use `ServeACPOptions.Projects`, `Tenants`, `Rights`, and `Represents`; `StdioActor` sets the complete operator principal instead of reading the launcher environment. Omit `Projects` to allow all projects supported by the composition; omit `Tenants` to allow only sessions without a tenant. Include `""` in an explicit tenant list to permit those sessions as well. An empty list permits no tenants or projects in its scope. Network rights are capped without replacing recorded grants; `$/ping` works before and after initialization with a default five-second deadline. The token is the only source of network connection identity; `MODULAR_AGENT_ACTOR` applies to stdio only.
- `ma --policy FILE` selects an operator file instead of the default `policy.json`. It sets `stdio`, WebSocket `actors`, and `limits` in all modes. `ma --acp --listen ADDR --token-file FILE` remains the local loopback shorthand; omit `--token-file` when the policy supplies `actors`. `ma --declaration` shows the effective limits without principals or credentials. `go/.bin/modular --serve-plugin --listen ADDR --token-file FILE` serves the conformance plugin and prints its bound URL. For the plugin kit, launch two more copies with `MODULAR_AGENT_PLUGIN_PARTS=runtime` and `durable-runtime`, and pass their URLs as `--runtime-url` and `--durable-runtime-url`.

**Named callers.** Use `ServeNamedServiceFactory` instead of a static plugin or a no-argument factory. Supply a nonempty `ServeOptions.Callers` table instead of `TokenFile`. Each `PluginCaller` has a distinct case-sensitive `CallerID` and a distinct owner-only `TokenFile`. To serve an environment, set `Projects` to the caller's operator-assigned directories. A caller's list cannot exceed a listener-wide list, if set. The factory gets the ID after the WebSocket upgrade authenticates. Use it to select retained state before setup sees any settings. It is not a session actor or a callback grant. Each socket gets its own instance, including two sockets with the same token. Rotate a credential by restarting with the replacement file. Run `go/scripts/check-named-callers.sh` for the managed one-listener kit.

### AG-UI on HTTP and SSE

`agent.ServeAGUI(ctx, modular.ServeAGUIOptions{Listen: address, Actors: actors})` returns a `*modular.Service` with the HTTP origin in `URL` and a `Close()` method. Use `ACP: true` and compose with `WithPluginHost(true)` to serve ACP at the root WebSocket path on that listener. Without TLS, listen only on loopback. `TLSOptions.ClientCAFile` requires a verified client certificate **in addition** to the bearer token.

Set `ClientID` on each `ACPActor`. Two tokens can share a client ID for rotation only with the same principal and scope. The optional `Tenant` selects the creation tenant. To admit a previously unrecorded actor, enable several actors and set `JoinOnOpen`. `Origins` is a list of exact browser origins. `TrustTrace` opts a token into AG-UI and ACP work context. ACP stdio trusts its launcher unless `ServeACPOptions.StdioTrustTrace` points to false. `TraceStateKeys` lists the vendor keys allowed on local work. The listener does not take context from reads, presence, upgrades, metadata or baggage.

Use the [binding routes](../../docs/bindings/agui.md). Replace provisional messages with the final snapshot. After a conflict, GET the thread again. Only a live success terminal authorizes frontend execution. Never run a tool from a snapshot or a partial stream. To answer an in-turn question, open presence **before** sending the run. The question manager marks presence by session, actor and client. A run marks presence but cannot receive an in-turn interrupt without the same pre-existing presence stream. An approval route belongs to one client's unchanged question view. Presence cannot authorize handling a secret. Closing a stream detaches it; it does not cancel its turn.

Approval interrupts in `RUN_FINISHED` and the snapshot's `waiting.questions` carry `metadata["modular-agent.approvalCall"]`: the same `{ name, input }` shown in the prompt, after tool gates. If the output gate changes or withholds the approval view, the client gets no interrupt for it. Use the object for display and answer the interrupt ID with `resume`.

**Following closed waits.** Take `waitCursor` from the authenticated thread snapshot. Read `host.WaitClosures(ctx, threadID, waitCursor)` and save each item's `Cursor` only after applying it. The feed reports the committed reason or Interface result status; it does not establish presence or grant the right to answer. On disconnect, reconnect with the last applied cursor. On `cursor_expired`, take a new snapshot. A new snapshot shows current waits, not the missing reasons.

**Looking up a run.** A kept thread's snapshot offers `runReceipts: 1`. Call `host.RunReceipt(ctx, threadID, runID)` on the same deployment with the same principal and client ID. `Terminal` describes release to the transport, not delivery. `Work` describes the linked admission, turn or continuation. Even a completed turn can have an unknown terminal. An interrupted exchange and its answer-only successor can have different receipts for the same turn. A missing receipt is not permission to repeat work.

**Listing threads.** `GET /agui/v1/threads` returns kept threads this client may watch, newest change first. Each row has only `threadId`, `updatedAt` and `waiting`. The counts describe eligible questions and open Interface calls on this route, not their content. A turn can end with a question or call still open. Listing does not open a session, join an actor or mark presence.

Pass `limit` (1–500, default 100). If the reply includes `next`, pass it as `after` on the next request. The cursor belongs to this client and listener. An unknown or expired cursor returns HTTP 400 with `invalid_request`. Each page reads current records.

Use `Agent.SessionSummary(ctx, id, viewer)` to read a kept session. Supply the authenticated actor, tenant, scope and executor route. `InTurn` identifies questions still offered on the live route. A missing or inaccessible session returns nil. AG-UI pages and ACP rows use the same read of each committed store record. Neither takes the writer lease. ACP has no tool executor route.

With a state plugin, set `StatePlugin` and supply its current revision and JSON document through `CurrentState`. Configure `RawSources` to project a named plugin's explicit `modular-agent.agui.raw` events. Other visible plugin events use `CUSTOM`. The output gate's recipient is the client ID. It can redact shared entries and streams; the adapter checks the final envelope again. A changed actionable envelope is withheld. No state plugin means no state events.

### Remaining ADR 0030 work

- The Go ledger charges queued input and output in the Harness, ACP attachment caches, and SDK event and prompt streams. It still does not bound every transport queue, open session, or connection. Logical storage accounts for portable encoded records and known obligations; it does not count all native metadata and sidecars or reserve physical disk. Not all terminal write paths use bounded records, notably recovery and unusually large turn output. The SDK does not yet prove settlement at every store and transport limit.
- The ACP output gate and update handoff recheck authority and erasure. The transport can queue an already checked reply; Go does not yet recheck inside the ACP library's final write queue. Direct tools and commands recheck after preparation, but there is not a single atomic barrier for every callback or external effect.
- The dedicated Go history service implements the optional `pendingErasure: 1` profile. Keep all participating readers and writers on a coordinated service. A file/snapshot adapter that can have writers outside the service lock does not offer HTTP erasure coordination. Existing raw Go service stores without a registry do not advertise it; do not initialize an empty registry to recover missing state. The operator must fence restores. The registry blocks stale copy publication and new views. It does not serialize an external dispatch or a transport write already in progress with intent publication.
- The Harness reconciles on acquire or authorized use and retains Provider deletion debt across restart. It has no autonomous sweep of unopened sessions. Interrupted work is settled without Runtime replay; unconfirmed physical job cleanup is recorded, not asserted. A held destination with an active job still needs its writer to stop the job or yield the lease. The kit passed **18/18** on each launcher in isolated runs. One concurrent run lost the writer before reaching the third injected fault on each launcher (**13/14** each); the cause was not established. Fault-injection failures now report the phase and recent history proxy timing and status without recording lease tokens or entry contents. A separate regression test shows that a blocked history response could prevent another session's lease from renewing. Valid renewals on the file-backed history service no longer wait for storage operations.

### Known gaps

One project-notes run reported `session interrupted; reopen to recover` during its ordinary scripted turn. The final run completed both cases, and all six ops-desk cases passed. The interruption did not recur in the diagnostic run; its cause is unresolved. No timeout or retry behavior was changed.

Held output uses the session, tenant and agent byte limits. The Harness gates ordered segments of at most 4 MiB, checks replacements and releases no pieces until the last segment passes. An overflow ends the affected AG-UI exchange with `RUN_ERROR`.
